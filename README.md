# ESP32-S3 Recoil Engine R3.3.1

Исправленная версия предоставленного скетча. R3.3.1 устраняет ошибку автогенерации
прототипов Arduino IDE 1.8.19: общие типы перенесены из .ino в EngineSafety.h.
При обновлении замените **оба файла вместе**. Алгоритмы движения не менялись.

Исходный файл пользователя не изменён.
Проект рассчитан на ESP32-S3 с **native USB OTG / TinyUSB**, не USB Serial/JTAG.

## Сборка

Проверена компиляция и линковка на Arduino-ESP32 **2.0.17**, Xtensa GCC
8.4.0 / esp-2021r2-patch5, платформе PlatformIO espressif32 **6.12.0**.
Конфигурация `platformio.ini`: ESP32-S3-DevKitC-1 N8, 8 MB QIO flash, без PSRAM.
Для другой платы выберите её реальный размер/type flash и PSRAM; адреса GPIO тоже
необходимо сверить со схемой. В частности, RGB на GPIO48 есть не на всех S3-платах.
Arduino-ESP32 3.x в рамках этой работы не проверялся.

PlatformIO:

```sh
pio run -e esp32-s3-native-usb
```

Arduino IDE: установите Espressif ESP32 2.0.17, откройте
`firmware/RecoilEngine/RecoilEngine.ino`. Файл `EngineSafety.h` должен лежать рядом
с `.ino`. Выберите свою ESP32-S3 плату и USB Mode **USB-OTG (TinyUSB)**,
USB CDC On Boot **Disabled**, Arduino/Event core **Core 0**, CPU 240 MHz.
Не выбирайте Hardware CDC and JTAG. Используйте разъём native USB, а не разъём
отдельного USB-UART преобразователя. Сам USB HID не передаёт нажатие ЛКМ: он
передаёт только перемещения, как и исходная прошивка.

## Что сохранено

Оба банка 40 × 30 узлов, таблица множителей, HID report descriptor и GPIO не
изменены. Сохранены CLOSE/LONG, 15 профилей, tap-огибающая, catch-up, Spring-Back,
warm-start, sustain-loop, амплитуды шума и дрейфа, зеркалирование и LED.
Побайтовое равенство этих таблиц и report descriptor исходнику проверено.

Сохраняется исходная политика старта: механизм включён после перезапуска;
профиль и режим загружаются из NVS. По умолчанию профиль 14 (множитель 3.0).
Состояние ON/OFF не сохраняется. Ступенчатая модель остывания и порог 320 мс
сохранены как часть исходной модели движения, а не заменены новой калибровкой.

Сохраняются жесты: двойной FN — ON/OFF, удержание FN — CLOSE/LONG.
Изменено распознавание двойного FN: команда выполняется на втором отпускании,
без дополнительного ожидания 250 мс; окно оценивается от первого отпускания до
второго нажатия. Долгое удержание отменяет ожидающий короткий жест.
Режим фиксируется на текущее удержание; профиль обновляется каждые 16 тиков,
как в исходнике. Переключение профиля в ноль очищает хвост фильтра и остатки.

## Исправления

- EMA фильтрует скорость и использует поправку смещения по разности состояний.
  При номинальном тике 1 мс это исходная EMA с alpha=0.30, с отличиями округления
  float. При переменном dt фильтр больше не создаёт лишнее суммарное смещение.
  Незавершённый хвост при отпускании намеренно отбрасывается, как раньше.
- Проверка возраста USB-остатка выполняется до отправки и на ready-пути.
  Просроченный транспорт остаётся помеченным до успешной постановки нулевого
  отчёта в очередь; при повторных отказах история не накапливается заново.
- При потере mount или USB suspend движение, возврат и warm-state очищаются.
  После восстановления нужен стабильный release перед новым нажатием.
- При длительном пропуске тиков очищаются старые остатки, фильтр и tap-долг.
- Дедлайн Spring-Back проверяется до отправки. Просроченный возврат не уходит.
- Между тиками движок блокируется по уведомлению от esp_timer, с коротким
  активным ожиданием в конце. Абсолютные дедлайны и jitter периода сохранены.
  Core 1 освобождается для системных задач; удаление Idle из watchdog убрано.
- Запись NVS начинается по согласованию с движком только после завершения
  активного движения и возврата. На время записи движок блокируется. Нажатие,
  которое оказалось удержанным по окончании записи, требует отпускания; старый
  пропущенный жест не воспроизводится задним числом.
- Ошибки открытия/записи NVS не маскируются; неудачные изменения остаются
  ожидающими сохранения и повторяются не чаще одного раза в 2 секунды.
- Проверяются запуск USB, создание таймера и постановка его на ожидание.
  При ошибке запуск/генерация останавливается с красной индикацией.
- Счётчики смещения для возврата ограничены временем tap-окна, чтобы не было
  переполнения signed int при чрезвычайно долгом удержании.

Красное мигание означает ошибку запуска/таймера. Янтарное мигание означает
ошибку хранения настроек. Обычные подтверждения кнопок имеют приоритет над
янтарной индикацией. TWDT движка подписывается только если watchdog уже
инициализирован SDK; статус доступен в диагностике, как и раньше.

## Проверки

```sh
bash tests/run.sh
```

Пройдены 6 групп математических/логических проверок и 10 сценариев выполнения
самого скетча с заглушками GPIO/USB/RTOS/NVS. Использованы AddressSanitizer и
UndefinedBehaviorSanitizer; LeakSanitizer отключён из-за ptrace облачного runner.
Проверены номинальная EMA, переменный dt и сохранение смещения, deadline USB,
таймаут возврата, жесты FN и rollover millis, удержание при старте, отключение и
suspend USB с удержанием, длительная занятость/отказы очереди, нулевой профиль,
flash-handshake и повтор записи после ошибки NVS.

Сборка PlatformIO ESP32-S3 прошла: 50 616 байт статической RAM; точный итоговый размер flash
и хеш скетча записаны в `VALIDATION.md`. В облаке реестр PlatformIO недоступен:
для проверки использованы локально упакованные официальные релизы Espressif
с GitHub, с проверкой SHA-256 по официальному package_esp32_index.json. Файлы
SDK/системных библиотек не патчились. esptool 4.9.0 и SCons 4.11.1 установлены
из PyPI. Обычный `platformio.ini` использует стандартные пакеты PlatformIO.

Дополнительно проверен Arduino Builder **1.6.1** (сборщик Arduino IDE 1.8.19)
с Arduino ctags **5.8-arduino11** на Linux. На R3.3 воспроизведены исходные
ошибки R32DiagSnapshot / R32TimeDynamics / R32CachedSpline; на R3.3.1 полная
сборка прошла с параметрами пользователя: 4 MB, QIO 80 MHz, Huge APP,
Core 1 / Core 1, TinyUSB, CDC/MSC/DFU Disabled, CPU 240 MHz.
Результат: flash 327 685 байт, RAM 50 480 байт. Добавлен отдельный тест
ранних прототипов Arduino IDE. Графическая IDE под Windows не запускалась.

## Что требует реальной платы

Компиляция и симуляция не подтверждают электрическую совместимость и реальные
USB-тайминги. На оборудовании ещё необходимо проверить короткий tap, длинное
удержание, быстрые повторные нажатия, OFF во время движения, reconnect/suspend
при удержании и сохранение профиля после выключения питания.

Подключение GPIO5 к существующей мыши допустимо только после проверки схемы,
общей земли и уровней 3.3 V. Нельзя подавать 5 V на GPIO ESP32-S3.

Spring-Back компенсирует отчёты, принятые USB-очередью. Ни очередь, ни USB ACK
не доказывают, что приложение обработало движение. Точное возвращение экранного
курсора невозможно обещать при ускорении, границах экрана и другом преобразовании
ввода. Ошибки транспорта обрабатываются отменой просроченного возврата.

`R32_USB_COMPLETION_HOOK` оставлен равным 0; внешний адаптер callbacks в ядре
не поставляется и не нужен для основной работы. Не включайте его без адаптера.
Аппаратный RNG и его амплитуды сохранены; качество энтропии конкретной сборки
не измерялось. Устройство не получает обратную связь от приложения или руки,
поэтому шум не является доказательством естественности движения.

Исходные VID/PID/USB-строки Logitech сохранены для совместимости исходного
проекта. Это не полная реализация Logitech G502 и не гарантия работы G Hub.
Для собственного распространяемого устройства используйте свои идентификаторы.
