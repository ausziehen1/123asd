# CLOSE / LONG: по 80 паттернов

В комплекте только два файла: PatternBanks80.h с массивами и эта инструкция.

В каждом банке 0–39 — прежние паттерны без изменения значений; 40–79 —
сглаженные варианты соответствующих исходных паттернов 0–39.
В каждом паттерне по 30 узлов; хвост зацикливается с узла 29 на узел 18.

## Что заменить в RecoilEngine.ino

1. Положите PatternBanks80.h в папку скетча рядом с RecoilEngine.ino.
2. Замените:
```cpp
#define NUM_PATTERNS             40
```
на:
```cpp
#define NUM_PATTERNS             80
```
3. Удалите из .ino ОБА старых массива целиком:
```cpp
DRAM_ATTR const BulletTarget PATTERN_CLOSE[NUM_PATTERNS][SHOTS_PER_SPRAY] = {
    // все старые значения CLOSE
};
DRAM_ATTR const BulletTarget PATTERN_LONG[NUM_PATTERNS][SHOTS_PER_SPRAY] = {
    // все старые значения LONG
};
```
На их месте вставьте одну строку:
```cpp
#include "PatternBanks80.h"
```
В R4.1.0 это место перед таблицей MULTIPLIERS. Саму MULTIPLIERS сохраните.
Подключение должно находиться ПОСЛЕ определения NUM_PATTERNS, SHOTS_PER_SPRAY
и подключения EngineSafety.h (объявление BulletTarget).

Можно вместо подключения заголовка вставить из него обе декларации массивов
прямо в .ino вместо старых. Тогда отдельный #include не нужен.

Выбор случайного паттерна и проверки индексов движка R4.1 уже используют
NUM_PATTERNS: автоматически участвуют все 80. Ползунок силы 0–150 сохраняет
своё назначение и не выбирает номер паттерна.

## Диапазон графического предпросмотра R4.1

Для выбора новых номеров на графике исправьте только ограничения индекса.

EngineeringMode.cpp, обработчик /preview:
```cpp
// Было:
tuning::parseInt(pattern->value().c_str(), 0, 39, index)
// Стало:
tuning::parseInt(pattern->value().c_str(), 0, 79, index)
```

EngineeringPage.h, HTML-поле с id="pattern":
- в подписи «Паттерн банка, 0–39» замените 0–39 на 0–79;
- у этого поля замените max="39" на max="79".

EngineeringPage.h, функция loadPreview():
```js
// Было:
if (!Number.isInteger(pattern) || pattern < 0 || pattern > 39) {
  message('Номер паттерна должен быть от 0 до 39.', true);
// Стало:
if (!Number.isInteger(pattern) || pattern < 0 || pattern > 79) {
  message('Номер паттерна должен быть от 0 до 79.', true);
```
Если в вашей версии нет графического предпросмотра, этот раздел не нужен.
Не заменяйте число 39 во всех файлах без разбора.

## Как подготовлены новые варианты

Сглаживание выполнено заранее по X/Y с учётом стыка петли 29 -> 18.
Отдельно сохранены суммы X/Y узлов начала (0–5), тела (6–17) и хвоста (18–29)
исходного аналога; максимальная ошибка после записи во float меньше 0,00002.
Это сохранение сумм узлов, а не обещание совпадения фактического смещения
после интерполяции, шума, фильтров, округления и USB.

Для каждого нового паттерна по каждой оси RMS второй разности узлов снижен
более чем на 60%. Это проверка плавности массива, а не физическое измерение.
Изменение формы и амплитуд может потребовать уточнения калибровки.
Шумовые параметры прошивки отдельно не изменены.

## Память и проверки

При DRAM_ATTR оба банка займут 38 400 байт вместо 19 200:
дополнительно 19 200 байт (18,75 КиБ) внутренней RAM.
Сглаживание не выполняется в игровом цикле; нового фильтра на каждый тик нет.
Формат NVS и сохранённые коэффициенты остаются прежними.

Проверены: по 80 x 30 узлов, точное сохранение исходных значений в float,
конечность чисел, положительный Y, отсутствие дубликатов среди новых вариантов,
суммы узлов трёх участков и снижение второй разности по обеим осям.
Полная прошивка в этом пакете отсутствует. Новая компиляция для платы не проводилась.
