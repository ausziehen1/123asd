# RecoilEngine R4.2.0 — архив заменяемых файлов

Для установленной R4.1.0 с Arduino-ESP32 2.0.17 / ESP32-S3 native USB.
В архиве только 10 новых/изменённых файлов firmware/RecoilEngine и эта инструкция.
Новые библиотеки, смена платформы и очистка NVS не требуются.

## Установка

Сохраните копию своего скетча. Скопируйте содержимое firmware/RecoilEngine/
в одноимённую папку вашего проекта с заменой файлов; новые .h положите рядом с .ino.
Если скетч хранится без папок firmware/, копируйте сами эти 10 файлов в папку
RecoilEngine рядом с вашим RecoilEngine.ino.
Собственные изменения пинов и констант старого .ino перенесите перед сборкой.
EngineeringConfig.h с вашим SSID, паролем и кнопкой этот архив не заменяет.
Соберите и загрузите обычным способом с прежними настройками USB и платы.

Включён ранее подготовленный банк по 80 паттернов CLOSE/LONG: 0–39 исходные,
40–79 сглаженные. Веб-предпросмотр принимает номера 0–79.
Ползунок силы остаётся отдельной шкалой 0–150 (0,00–3,00).

## Оптимизация

- При нулевом джиттере периода больше не вызывается RNG для периода.
- Обратная длительность сегмента вычисляется при смене сегмента.
- Коэффициент RC микрошумa общий для X/Y и кэшируется по dt и microMs.
- Сила, горизонтальный множитель и уровень шума пересчитываются при смене силы/режима.
- Формулы движения, tap/catch-up, фильтры, защита USB и алгоритм ожидания тика сохранены.

Исключение лишнего RNG-вызова меняет случайную последовательность относительно
прежней прошивки. Поэтому конкретный случайный тест не обязан совпадать с R4.1.
Для проверки математики использована контрольная R4.1 с тем же банком 80 и тем же
исключением RNG-вызова; в ней отсутствуют новые кэши, замер времени и запись.

## Измерение обработки тика

В разделе последнего удержания и diagnostics.csv добавлены min/mean/max времени
обработки, минимальный оценочный запас до следующего срока и число превышений.
Используется счётчик тактов Core 1; частота CPU фиксируется в отчёте.
Плановое ожидание между тиками исключено. Холодный запуск удержания и завершающий
тик включены; количество замеров поэтому может отличаться от числа тиков движения.
В замер попадают прерывания и вытеснение задачи. Это прошедшее время обработки,
а не точный процент загрузки CPU и не подтверждение завершения USB-передачи.
Собственное обновление счётчиков и публикация итогового отчёта не входят в замер.

Для отдельного сравнения можно собрать с -DENGINE_COMPUTE_TIMING=0.
По умолчанию замер включён. Реальные значения времени появятся только на плате.

## Запись следующего теста

1. Войдите в инженерный режим, откройте http://192.168.4.1.
2. При необходимости измените коэффициенты и дождитесь сохранения.
3. Нажмите «Записать следующий тест».
4. Выйдите физической кнопкой настройки. После служебного перезапуска запись
   будет разрешена только для ПЕРВОГО следующего удержания.
5. Выполните удержание и отпустите микрик. Снова включите инженерный режим.
6. Нажмите «Показать запись». Можно скачать JSON с данными и испытанными
   коэффициентами либо CSV с приращениями.

Фиксированный буфер внутренней RAM — 4096 записей по 8 байт (32 КиБ).
При 1000 записях/с это 4,096 с; если отчёты отправляются реже, времени помещается больше.
Сохраняются только отчёты, принятые TinyUSB. Занятые/отклонённые попытки не записываются.
Запись заканчивается при отпускании, входе в настройку, USB loss или OFF.
Возврат Spring-Back после отпускания не входит в запись — это указано на странице.
После заполнения буфер сохраняет начало, отмечается неполная запись; мышь продолжает
работу. Другие удержания не перезаписывают этот первый тест.
При обычном запуске запись выключена. Армирование одноразовое, через служебный
software restart; во флеш/NVS оно не сохраняется и при отключении питания не действует.
Память буфера резервируется и при выключенной записи.

Данные RAM теряются при следующем перезапуске: скачайте файл до выхода.
В JSON хранится снимок испытанных коэффициентов; движение ползунков его не изменяет.
В CSV t_us — время расчётного тика относительно начала удержания, dx/dy — знаковые
HID counts. Это не время завершения USB-транзакции и не измерение курсора/приложения.
Начальные нули десятичного времени и явные знаки X/Y в CSV намеренные.
Нулевая сумма перемещений или отсутствие отчётов также являются допустимым результатом.

В игровой задаче нет HTTP, записи флеша, формирования строк, malloc и рисования.
CSV передаётся небольшими блоками из замороженного буфера только после остановки
движка; целый CSV-файл в RAM ESP не собирается. Графики строит второй ноутбук.

## Проверки и ограничения

Проверены сборка для ESP32-S3 с прежними версиями библиотек, Arduino early prototypes,
22 прежних сценария интеграции, сохранение/восстановление NVS, HTTP-защита, UI,
малые блоки CSV, переполнение/заморозка записи, USB busy/rejects/loss,
переполнение счётчика тактов, превышение бюджета и режим без замера времени.
Сравнены 320 контрольных трасс (80 паттернов x 2 режима x 2 модели) с записью ON/OFF.

Физические замеры на ESP32-S3 в этой среде недоступны. Результаты модельных тестов
и успешная компиляция не являются измерением фактической стабильности 1000 Гц.
Первые испытания проведите на стенде и оцените новые показатели обработки тика.

## Состав патча и результат сборки

Изменённые файлы: RecoilEngine.ino, EngineeringMode.cpp, EngineeringMode.h,
EngineeringPage.h, MotionReport.h.
Новые файлы: ComputeTiming.h, TickTimer.h, TickMathCache.h, TraceCapture.h,
PatternBanks80.h.

Контрольная сборка: PlatformIO espressif32 6.12.0, Arduino-ESP32 2.0.17,
AsyncTCP 3.3.2, ESPAsyncWebServer 3.6.0, ESP32-S3 240 МГц, TinyUSB mode 0.
Статическая RAM — 127 832 байта; Flash — 917 409 байт.
Это размеры сборки, не замер свободного heap во время работы Wi-Fi.

Изменение по сравнению с R4.1: +19 200 байт на расширенные банки, 32 КиБ
на запись и небольшой объём на метаданные/замер. При уже установленных банках 80
эта часть увеличения RAM повторно не добавляется.
