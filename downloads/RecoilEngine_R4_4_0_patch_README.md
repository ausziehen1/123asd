# RecoilEngine R4.4.0 — патч поверх R4.3.0

Архив содержит **только 10 новых/изменённых файлов скетча** и эту инструкцию.
База: ранее опубликованный `RecoilEngine_R4_3_0_patch.zip`, установленный поверх R4.2.
Это исходный код для сборки; готовый бинарный образ в патч не включён.

## Установка

1. Сделайте копию своей текущей папки скетча R4.3. При необходимости экспортируйте настройки JSON из инженерного режима.
2. Откройте архив и скопируйте **содержимое `firmware/RecoilEngine/`** в свою папку, где уже лежит `RecoilEngine.ino`, с заменой одноимённых файлов. В Arduino IDE не нужно открывать отдельный пустой проект из патча.
3. Обязательно добавьте новый **`MotionGenerator.h`**. Остальные девять файлов заменяются.
4. Сохраните свои `EngineeringConfig.h`, `PatternBanks80.h`, `EngineSafety.h`, `build_opt.h`. Они не менялись и в архив не включены. Удалять файлы после этого патча не требуется.
5. Соберите и загрузите скетч. Проверенная целевая конфигурация: **ESP32-S3, Arduino ESP32 core 2.0.17, USB-OTG / TinyUSB**, CPU 240 МГц. В Arduino IDE 1.8.19: Arduino Runs On Core **0**, Events Run On Core **0**, USB CDC On Boot **Disabled**. EngineTask закреплён за Core 1 самим кодом.
6. Используйте прежние библиотеки: **AsyncTCP 3.3.2**, **ESPAsyncWebServer 3.6.0**. Переподключитесь к инженерной странице и обновите её, чтобы браузер загрузил новый интерфейс.

Инженерный режим: прежняя физическая кнопка, по умолчанию **GPIO9 → GND**; адрес **http://192.168.4.1**. SSID, пароль и ваш пользовательский пин берутся из сохранённого `EngineeringConfig.h`.
Выход той же кнопкой сохраняет настройки, выключает сервер/Wi-Fi и выполняет программный перезапуск для освобождения сетевых ресурсов. FN и GPIO5 сохраняют свои назначения. Включение режима по удерживаемому после загрузки триггеру по-прежнему запрещено до его отпускания.

## Общая сила теперь означает темп

Шкала остаётся прежней: **0–150 шагов**, один шаг **0,02×**, максимум **3,00×**. Значение **50 = 1,00×** — нейтральный темп.

Сила продвигает внутреннее время паттерна, а не умножает амплитуду его основы. Повышение темпа позволяет пройти тот же участок быстрее. Начало, тело и хвост ускоряются в одинаковой пропорции, включая повтор хвоста. Частота расчётных тиков остаётся номинально **1 кГц**.

Пример: если при 1,10× проход занимал 3 секунды, то при 1,50× он займёт примерно `3 × 1,10 / 1,50 = 2,2 секунды`. Суммарное смещение основы за проход не умножается на 1,50. Существующая случайная вариация интервалов сохраняется; точная длительность разных удержаний может немного различаться.

**Перенесённое старое значение силы сохраняется численно, но получает новый смысл.** Например, сохранённые 150 теперь означают темп 3,00×. Войдите в инженерный режим и проверьте значение; для исходного темпа установите 1,00×. Автоматически восстановить прежнее ощущение от регулятора амплитуды одним пересчётом невозможно.

При темпе 0× основа остановлена. Дополнительный шум остаётся активным согласно собственному регулятору; полное выключение устройства выполняется FN.

## Горизонталь и независимый шум

**Горизонталь основы: 0–300%.**

- 0% — горизонтальная составляющая основы убрана.
- 100% — исходная горизонталь.
- 200% — ×2.
- 300% — ×3.

Направление этим регулятором не инвертируется. Заложенные в массив паттерна горизонтальные колебания являются частью основы и масштабируются вместе с ней.

**Интенсивность дополнительного шума: 0–200%.** 0% полностью отключает добавленный шум, 100% сохраняет базовую амплитуду. Шум добавляется после преобразований основы, независимо от темпа, горизонтали, сглаживания и трёх вертикальных регуляторов. Даже при горизонтали основы 0% он может двигать курсор влево-вправо. Его временная связность рассчитывается по реальному времени, поэтому увеличение темпа не ускоряет дрожь вместе с паттерном.

## Сглаживание и три вертикальных регулятора

**Сглаживание вертикали: 0–100%.**

- 0% сохраняет оригинальную вертикальную структуру с ручными поправками.
- Промежуточные значения плавно смешивают исходную подачу и равномерное движение.
- 100% даёт одинаковую вертикальную скорость основы между участками и внутри них, если ручные поправки сброшены.

Средняя подача рассчитывается для конкретного выбранного паттерна: интегральное смещение за первый проход делится на суммарное время этого прохода. В расчёт входят реальные сплайны и выбранные генератором интервалы, включая их разброс. Это усреднение по времени, а не просто одинаковый шаг каждого сегмента. Та же средняя подача сохраняется в зацикленном хвосте.

Три ползунка **Начало / Тело / Хвост** показывают итоговые значения **0–300%**: 100% соответствует исходному масштабу участка, 300% — тройному. При изменении сглаживания они автоматически пересчитываются. Значения округлены до целого процента для управления; автоматическое выравнивание внутри генератора выполняется непрерывно по времени.

Ручная доводка хранится отдельно как поправка в процентных пунктах. Например, если автоматическое значение начала равно 110%, а вы установили 120%, сохраняется поправка +10 п.п. При дальнейшем изменении сглаживания она добавится к новому автоматическому значению. Кнопка **«Сбросить ручные поправки»** обнуляет только эти три поправки текущего режима.

Эти три регулятора действуют на **Y**, а не на X. Полное обнуление участка обнуляет именно его вертикальную основу; горизонталь и независимый шум продолжают подчиняться своим регуляторам. Переходы между разными ручными настройками сглажены. Значение 100% общего сглаживания с последующей ручной доводкой уже может давать разные скорости участков — это ожидаемый результат ручного изменения.

Банки **80 CLOSE + 80 LONG**, их массивы, балансировка узлов, характер сплайнов, случайная зеркальность и продолжение после короткого перерыва сохранены. Неизменность `PatternBanks80.h` проверена побайтно. Нейтральные регуляторы возвращают исходную геометрию; побитового совпадения всего USB-потока с R4.3 нет: изменились смысл силы, стартовая обработка и способ интегрирования движения.

## Стартовое окно 15–25 мс

Вместо `TAP_WINDOW_US = 50000ULL` используются границы:

```cpp
#define TAP_MIN_US 15000ULL
#define TAP_MAX_US 25000ULL
```

Продолжительность выбирается **один раз на нажатие** и остаётся постоянной до отпускания. Блокирующего ожидания нет: оригинальная составляющая плавно набирает подачу. Стартовая огибающая встроена в плавное продвижение фазы первого сегмента; накопленное отставание возвращается к его концу без отдельного сбрасываемого долга смещения. При восстановлении частичной фазы обработка учитывает оставшуюся часть сегмента.

То же выбранное окно используется для распознавания короткого нажатия, учёта отправленного смещения и возврата. В предпросмотре оно проходит через тот же генератор. При сглаживании вертикали 100% равномерная составляющая Y обходит стартовое подавление; оно остаётся у оригинальной составляющей и горизонтали. Это позволяет получить действительно равномерную основу при полном сглаживании.

## Предпросмотр итогового HID-выхода

Рабочий режим и `/preview` используют **один `movement::Generator`** и **один `movement::Quantizer`**. Предпросмотр выполняет отдельный расчёт без отправки USB-команд: геометрия, темп, временной разброс, стартовая обработка, сглаживание, ручные поправки, фильтры, независимый шум, накопление дробных остатков, округление и ограничение 16-битного HID.

На рисунке складываются **целочисленные dx/dy**, а не исходные дробные значения паттерна. Небольшое колебание, которое не пересекло порог округления HID, не превращается в нарисованный зигзаг. Оси имеют **одинаковый масштаб**, без отдельного растягивания X. Границы изображения учитывают исходную тихую траекторию и весь рассчитанный текущий вывод, поэтому видна реальная пропорция отклонений.

Показываются первый проход и один полный повтор хвоста — около 42 сегментов; при темпе 0× показываются 3 секунды дополнительного шума. В расчёте используется каждый тик 1 мс. Для ограничения памяти/размера ответа на рисунок передаётся до 1208 точек накопленной целочисленной траектории. При медленном темпе точки выбираются реже; полный расчёт и границы всё равно учитывают все тики. Подпись показывает длительность, выбранное стартовое окно и интервал меток времени. Цвета обозначают начало, тело и хвост.

Для сравнения ползунков используется воспроизводимый seed. Номер 0–79 выбирает только паттерн предпросмотра; реальная работа сохраняет автоматический выбор. Предпросмотр начинается холодным стартом с исходной зеркальностью +1. Следующее реальное удержание может выбрать другой паттерн, зеркальность, интервалы и шум. Реальные задержки/занятость USB и восстановление частичной фазы после отпускания также не предсказываются. Совпадение команды в команду возможно при одинаковых начальном состоянии, случайных значениях, шагах времени и доступном USB.

Единицы графика — **HID counts**, а не экранные пиксели: чувствительность, ускорение ОС и обработка игры находятся за пределами этой модели.

**Запись реальных команд, логи движения, диагностические графики, CSV и отчёты не добавлены.** Расчёт предпросмотра запускается только после подтверждённой остановки EngineTask в инженерном режиме.

## NVS и совместимость настроек

Используется schema **5**. Два NVS-слота с поколением, CRC и проверкой чтением сохранены. JSON/NVS схем 2, 3 и 4 принимаются; при переносе старой вертикальной шкалы выполняется `новое сглаживание = 100 − старая вертикальная форма`. Существующие ручные поправки и интенсивность шума сохраняются. Старый раздел профилей не стирается; новая запись сохраняется в формате 5. Обратная загрузка настроек schema5 в старую прошивку не поддерживается — сохраните прежний JSON для отката.

В JSON поля `start/body/tail` хранят **ручные поправки**, а не показанные итоговые положения ползунков; `vertical` хранит процент сглаживания. Автоматическая часть зависит от конкретного паттерна и рассчитывается заново.

## Выполненные проверки

- Успешная сборка под ESP32-S3 / Arduino ESP32 **2.0.17** с указанными версиями сетевых библиотек. Отдельно проверена совместимость ранних прототипов Arduino IDE 1.x.
- Для всех 80 паттернов каждого режима: точное совпадение каждой выбранной точки предпросмотра с накопленным целочисленным выводом рабочего генератора и квантователя.
- Для тех же 160 комбинаций: равномерная Y-подача при 100% сглаживания, переменном dt и переходах хвоста; время/дистанция при смене темпа 1,10× → 1,50×.
- Проверены горизонтальное усиление ×3, независимый шум, точный ноль вертикальных участков, монотонность стартовой огибающей, неизменность выбранного окна в рамках нажатия.
- Проверено совпадение настоящего EngineTask с отдельным расчётом при одинаковых временах тиков; запуск с удерживаемым триггером, FN OFF, USB busy/reject/disconnect, пауза перед Wi-Fi, продолжение после короткого перерыва.
- Проверены CAS/защита HTTP, перенос JSON/NVS, CRC, повреждённый новый слот, ошибки записи/повтор, сохранение перед выходом. Тесты C++ выполнены с AddressSanitizer/UndefinedBehaviorSanitizer.
- Проверена JS-логика ползунков, автоматических значений и ручных поправок, очереди Fetch, устаревших ответов и одинакового масштаба X/Y.

В проверочной сборке: **статическая RAM 94 548 байт**, столько же, сколько в R4.3; Flash **854 513 байт**. Буфер предпросмотра выделяется динамически только в инженерном режиме. Сравнение не является замером времени исполнения на ESP32. Физическое устройство в этой среде не подключено; стабильность USB и реальные сроки тиков нужно подтвердить вашим испытанием.
