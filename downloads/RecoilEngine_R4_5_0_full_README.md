# RecoilEngine R4.5.0 — полный проект ESP32-S3

Это **полный согласованный проект**, а не патч. Все 15 файлов скетча уже находятся вместе. Старые патчи для его сборки не нужны. Приложены установочные ZIP двух сетевых библиотек из использованных при проверке исходников с их лицензиями.

## Что делать в Arduino IDE 1.8.19

1. Распакуйте архив в **новую отдельную папку**.
2. Откройте **`RecoilEngine/RecoilEngine.ino`** внутри распакованного проекта. В этой же папке находятся все нужные `.h`, `.cpp` и `build_opt.h`.
3. В менеджере плат установите **esp32 by Espressif Systems 2.0.17**. Выберите **ESP32S3 Dev Module**.
4. Установите библиотеки через **Скетч → Подключить библиотеку → Добавить .ZIP библиотеку**:
   - `libraries/AsyncTCP-3.3.2.zip`;
   - `libraries/ESPAsyncWebServer-3.6.0.zip`.
   Если они уже стоят, проверьте именно эти версии. При наличии нескольких копий `AsyncTCP` или `ESPAsyncWebServer` оставьте соответствующие версии в папке Arduino libraries; IDE сообщает путь фактически выбранной библиотеки в подробном выводе сборки. При установке приложенных ZIP исходный код библиотек не менялся; примеры и служебные файлы репозитория из установочных ZIP исключены.
5. Параметры платы:

   | Параметр | Значение |
   |---|---|
   | USB Mode | **USB-OTG (TinyUSB)** |
   | USB CDC On Boot | **Disabled** |
   | CPU Frequency | **240 MHz** |
   | Arduino Runs On | **Core 0** |
   | Events Run On | **Core 0** |
   | Flash Mode / Frequency | **QIO / 80 MHz** |
   | Flash Size | **4 MB** для вашей ранее указанной конфигурации |
   | Partition Scheme | **Default 4MB with spiffs** |
   | PSRAM | **Disabled**, как в прежней конфигурации |

   EngineTask сам закрепляется за Core 1. Полный проект проверен без PSRAM и помещается в стандартный раздел приложения 1,25 МиБ.
6. Соберите и загрузите проект. Сохранённые NVS-настройки читаются с переносом старых форматов; стирать флеш для штатного обновления не требуется.
7. Нажмите инженерную кнопку, подключитесь ко вновь появившейся Wi-Fi-сети и откройте **http://192.168.4.1**. В уже открытой вкладке нажмите **Ctrl+F5**, чтобы загрузить новую страницу и новую сессию.

## Пины и подключение

- **GPIO5 → GND**: вход удержания ЛКМ.
- **GPIO6 → GND**: FN, двойное нажатие — ON/OFF, удержание — CLOSE/LONG.
- **GPIO9 → GND**: вход/выход инженерного режима; внутренний pull-up включён.
- **GPIO48**: RGB-индикация, как в прежнем проекте.
- GPIO7/8 не используются для выбора силы или профиля.

Параметры точки доступа и инженерный пин находятся в **`EngineeringConfig.h`**. В комплекте стандартные значения:

- SSID: **Keenetic-512**;
- пароль: **S3Tune-512!**;
- адрес: **192.168.4.1**.

Если в своём экземпляре вы назначали другой пин или пароль, перенесите именно эти значения в новый `EngineeringConfig.h`. Остальные файлы нового проекта уже согласованы между собой.

При входе инженерного режима HID приостанавливается до запуска Wi-Fi. После настройки дождитесь «Сохранено» и нажмите GPIO9: сервер выключится, настройки сохранятся, ESP программно перезапустится и освободит сетевые ресурсы. Во время инженерного режима HID-движение не отправляется.

## Что исправлено после R4.4

По описанию отключалась сама точка доступа с погасшей индикацией, поэтому это нельзя объяснить только ошибкой браузера. Без журнала загрузки/сброса конкретная причина аппаратного перезапуска не подтверждена. В коде устранены два существенных источника нагрузки: длительный расчёт предпросмотра внутри AsyncTCP-обработчика и сборка полного большого JSON в динамической строке.

Теперь:

- `/preview` только ставит расчёт в очередь и быстро возвращает `202 pending`, пока результат не готов.
- Расчёт выполняет **ControlTask**, не более **256 виртуальных тиков за проход**, с обычной паузой FreeRTOS между проходами. Сетевой обработчик не рассчитывает весь паттерн за один вызов.
- Для готовой траектории используется **один буфер около 10 КБ**, выделяемый только в инженерном режиме. Пока HTTP-ответ передаёт данные, буфер защищён от изменения.
- JSON передаётся небольшими порциями из этого буфера. Ответ целиком не копируется в большой `String`; повторные и частичные чтения проверены.
- При нехватке памяти возвращается ошибка с повтором через паузу, а точка доступа продолжает работать.
- Правки при непрерывном движении ползунка объединяются; завершённые промежуточные траектории могут отображаться во время дальнейшего перетаскивания.
- Разовый обрыв Fetch больше не блокирует интерфейс навсегда. Страница повторяет HTTP-запросы, сохраняет локальные правки и проверяет, успел ли сервер принять запрос, ответ которого потерялся.
- Новый запуск контроллера или несовпадение версии страницы/прошивки дают понятное сообщение о необходимости обновить страницу, а не отправку несовместимых настроек.

Это программные исправления проверенных мест риска. Физическая ESP в среде разработки не подключена; испытание конкретного питания, платы и радиосвязи остаётся на устройстве.

## Регуляторы

**Общая сила вновь регулирует величину смещений основы X/Y**, как в исходной логике, а не скорость прохождения фаз, как в R4.4. Шкала: 150 шагов, 0,00–3,00×; шаг 50 соответствует 1,00×. Длительности начала, тела и хвоста сохраняются. За одно и то же время большая сила даёт большее смещение; фиксированную дистанцию курсор поэтому может пройти быстрее, но сама последовательность фаз не сжимается во времени.

- **Горизонталь основы 0–300%**: 0 — убрать основу X, 100 — исходное, 300 — ×3; направление сохраняется.
- **Шум 0–200%**: независимый дополнительный шум. Только его собственный 0 полностью выключает его; общая сила и горизонталь его не масштабируют. При нулевой основе шум по-прежнему может двигать курсор.
- **Сглаживание вертикали 0–100%**: 0 — исходная структура; 100 — равномерная вертикальная основа. Средняя подача рассчитывается из реального интегрального смещения и продолжительности участков выбранного паттерна.
- **Начало / тело / хвост 0–300%**: автоматически показывают рассчитанные коэффициенты и допускают ручную доводку. Ручные поправки сохраняются отдельно в процентных пунктах; их сбрасывает соответствующая кнопка. Эти три регулятора действуют на Y.
- Стартовое окно выбирается один раз на нажатие в пределах **15–25 мс**, вместо прежних 50 мс. Огибающая плавно возвращает отставание к концу первого сегмента. Полностью выровненная составляющая Y обходит стартовое подавление.

Банки **80 CLOSE + 80 LONG** не менялись. Сохраняются сплайны, разброс интервалов, зеркальность, зацикленный хвост и продолжение после короткого перерыва. Независимый шум и ручные изменения остаются поверх автоматически выровненной основы; при них сглаживание 100% не обязано давать строго прямую линию.

## Что показывает рисунок

Предпросмотр использует тот же `movement::Generator` и тот же квантователь, что и рабочий режим: все настройки, фильтры, шум, дробные остатки, округление и ограничение HID. Координаты складываются из **целочисленных HID-команд**, оси X/Y имеют одинаковый масштаб. Запись реальных тестовых команд, CSV, отчёты и диагностические графики не добавлены.

Расчёт идёт по каждому тику 1 мс. На рисунок передаётся выборка примерно раз в 8 мс, до 640 точек; границы учитывают все рассчитанные тики. Показаны первый проход и один повтор хвоста. Seed воспроизводимый для сравнения ползунков. Номер паттерна 0–79 выбирает только предпросмотр; в рабочем режиме выбор остаётся автоматическим.

Предпросмотр — прогноз холодного старта с заданным seed и исходной зеркальностью +1. Другая случайная последовательность, другой выбранный паттерн, восстановление после отпускания или занятость USB могут изменить конкретное удержание. Чувствительность и ускорение ОС/игры не входят в график: его единицы — HID counts.

## Настройки и проверка сборки

Новый формат — **schema 6**. Читаются старые JSON/NVS 2–5; шкала старой вертикальной формы из 2–4 переносится в сглаживание как `100 − старое значение`. В schema5/6 `start/body/tail` хранят ручные поправки, а не итоговые показания трёх ползунков. Численное значение силы сохраняется, но в R4.5 оно снова означает амплитуду; при переходе с временной трактовки R4.4 проверьте его. Два слота NVS, CRC и проверка записи чтением сохранены.

Выполнены целевая сборка ESP32-S3 / Arduino ESP32 **2.0.17**, проверки прототипов Arduino IDE 1.x, C++-тесты ASAN/UBSAN и JS-тесты интерфейса. Для всех 160 комбинаций банк/режим проверены итоговые HID-точки предпросмотра, выравнивание и независимость таймингов от общей силы. Отдельно проверены USB busy/reject/disconnect, FN OFF, пауза перед Wi-Fi, NVS/JSON, нехватка памяти предпросмотра, непрерывное перетаскивание и потеря запросов/ответов.

Отдельно успешно собран проект, распакованный из готового архива, с библиотеками из комплекта.

Проверочная сборка: **RAM 94 756 байт**, **Flash 859 037 байт**; стандартный раздел приложения **1 310 720 байт**. Это данные сборки, не замер времени исполнения на физической ESP.
