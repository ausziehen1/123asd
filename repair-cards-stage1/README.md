# Карточки ремонта — 0.4.0

Локальные SQLite и C++ сервер, отдельные Windows-приложения **Креатор** и **Ридер**, редактор Excel-бланка в браузере, QR карточек и передача партии этикеток в **BarTender 10.1**.

**Обновление, первый QR, макет, предпросмотр и печать: [docs/QR_PRINT_READER.md](docs/QR_PRINT_READER.md).**

Полный ZIP содержит исходники для **CLion + MinGW64** и папку `ready-windows` с готовыми EXE для Windows 10 x64. Библиотеки и браузерные ресурсы включены; Интернет для работы приложения не нужен. BarTender и драйвер Zebra устанавливаются отдельно на печатающем ПК.

## Возможности

- Креатор: типы платформ, начальный ID, регистрация партии, подсказка следующего ID каждого типа, фильтр и список.
- Внутренний номер SQLite уникален. Введенные номера продукции могут повторяться; каждая запись имеет отдельный бланк и QR.
- Редактор: ячейки, оформление, строки, столбцы и объединения. Сохранение состояния и текущего XLSX вместе; защита от перезаписи устаревшим редактором.
- QR: ссылка `http://сетевой-адрес:8080/cards/внутренний-ID`, открывающая сохраненный бланк для просмотра. Подготовка выбранных записей или всей последней партии.
- Креатор открывает QR в редакторе; Ридер — только для просмотра. На телефоне подходит обычная камера и браузер.
- BarTender: редактирование рабочего `.btw`, расположение элементов, точный предпросмотр и стандартный диалог печати с выбором Windows-принтера и его свойств.

Предоставленный `TEST.btw` включен без изменения. При первом подключении нужно связать QR-объект с полем `QRUrl` и сохранить рабочий шаблон. Печатать бланки не требуется.

## Запуск и данные

Для существующего проекта сначала остановите сервер и Креатор, сохраните копию папки `data` и своего конфига, затем обновите файлы по инструкции. Рабочая база в архив не включена. Схема обновляется автоматически до версии 3; карточки, бланки и номера сохраняются.

Готовые EXE лежат в `ready-windows`. Их конфиг использует `../data/repair.sqlite3`: после обновления существующего проекта это та же база в корне. При нестандартном пути сначала перенесите свои настройки в этот конфиг. Сервер запускается двойным щелчком; его консоль нужно оставить открытой. Не запускайте одновременно второй сервер из CLion.

Для сборки в CLion задайте у `repair_server` аргументы `--config config.example.json` и рабочую папку с `CMakeLists.txt`. Новый конфиг слушает `0.0.0.0:8080`; в браузере своего ПК открывайте http://127.0.0.1:8080. В QR выбирается реальный сетевой адрес ПК.

Для резервной копии остановите сервер и скопируйте всю папку `data`. Не удаляйте базу ради сброса нумерации: внутренние номера используются в напечатанных QR.

Учетных записей и паролей нет. Ридер предоставляет интерфейс просмотра; сервер не разграничивает права между пользователями сети.

## Проверка

Пройдены четыре группы C++ тестов, HTTP API, независимое распознавание QR и редактор в Chromium. Все три Windows EXE собраны кросс-компилятором и проверены на отсутствие дополнительных DLL компилятора. Фактический запуск новых окон на Windows, BarTender 10.1 и печать Zebra S4M требуют проверки на пользовательском ПК. Подробности: [VALIDATION.md](VALIDATION.md).

## Для разработчика

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
python tests/api_test.py build/repair_server
```

Дополнительные интеграционные проверки требуют Python-зависимостей только на проверяющем ПК:

```sh
python -m pip install Pillow zxing-cpp==2.3.0 playwright openpyxl
python tests/qr_test.py build/repair_server build/labels_tests
python tests/editor_test.py build/repair_server /usr/bin/chromium
```

Последний тест использует установленный Chromium по указанному пути. Python не требуется пользователям программы.
