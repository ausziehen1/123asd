# Repair Cards 0.6.0

C++ сервер + SQLite на одном Windows-ПК и три однофайловых клиента для локальной сети: **Creator**, **Reader**, **Repair**.

**[Полная инструкция: установка, перенос базы, совместная работа, печать, копии и обновления](docs/USER_GUIDE.md)**.

- Пользователям передается один EXE из `clients`: DLL/Updater встроены и распаковываются в LocalAppData. Можно запускать несколько экземпляров каждого приложения.
- Все обращения к SQLite идут через один сервер. FIFO-очередь, WAL, транзакции и резервирование через SQLite Backup API.
- Сохранения новых клиентов автоматически объединяют изменения разных ячеек. Одна ячейка получает последнее значение в очереди. Пересекающиеся структурные изменения заменяют лист. Предыдущие версии доступны через «История».
- Открытые бланки получают обновления примерно раз в секунду, списки Creator — раз в три секунды. Активный ввод и несохраненные местные правки сохраняются.
- Creator регистрирует диапазоны с явно введенного Table ID, назначает коды 1С группами «количество / код» с плюсом справа и готовит отдельные задания BarTender.
- Reader показывает встроенное окно просмотра, Repair/Creator — встроенный редактор со свободными строками/столбцами и сохранением.
- Код 1С синхронизируется между SQLite, бланком, XLSX и полем OneCCode для BarTender. QR использует Unique ID, внешние Table ID могут повторяться.
- Будущие локальные обновления: замена одного EXE или ZIP-патч DLL через Updater с проверкой SHA-256, резервной копией и откатом.

Для встроенного бланка нужен установленный Microsoft WebView2 Runtime Evergreen x64. Для печати Creator использует BarTender 10.1 SR3 и драйвер Zebra; Excel, Qt, Python и Node.js для обычной работы готовых программ не нужны. База должна находиться на локальном диске сервера, не на SMB/сетевом диске.

В полном архиве `ready-windows` содержит сервер, repair_backup.exe и обычный комплект EXE/DLL. Для распространения **одного файла** используйте `clients/Creator.exe`, Reader.exe или Repair.exe. Исходники и зависимости включены; CMake-цели `repair_*_portable` генерируют однофайловые варианты. Для сборки этих вариантов разработчику нужен Python 3.

При переходе с 0.5 сначала сохраните базу и обновите сервер до схемы 5 по инструкции, затем замените все клиенты. Старые версии клиентов не используют новую очередь и живое обновление. Учетных записей по требованиям нет; роли задают интерфейс, API без авторизации.
