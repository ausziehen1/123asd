# Проверка Repair Cards 0.5.0

## Выполненные проверки

- Linux: шесть групп C++ тестов — `core_tests`, `client_tests`, `document_tests`, `labels_tests`, `one_c_tests`, `update_tests`.
- API: регистрация, повторяющиеся Table ID, фильтры, копии бланков, ошибочные входные данные, конкурирующие запросы и перезапуск.
- QR: независимое распознавание zxing-cpp, отдельные ссылки при одинаковых Table ID, UTF-8 CSV и сохранение сетевых настроек.
- Браузер Chromium: реальный ввод, Ctrl+S, вставка строки/столбца, оформление, текущий XLSX, конфликт редакторов, режим просмотра и мобильный размер.
- Коды 1С: распределение 2/7/1, явный пустой код, ведущие нули, SQLite и XLSX вместе, откат всей операции при конфликте или отсутствующей карточке.
- Поле 1С: перемещение с исходной J5 в K6 после вставки строки и столбца; служебная привязка и именованная область XLSX сохраняются. Повторное назначение кода обновляет новую ячейку.
- Миграция базы 3 → 4 с извлечением ранее заполненного кода 1С из настоящего XLSX; старые ID и последовательности сохраняются.
- Проверена гонка загрузки: устаревший ответ metadata карточки не подменяет более свежий код 1С из атомарного снимка документа.
- Встроенный режим: сообщения о несохраненных правках и сохранении перед закрытием, отсутствие элементов редактирования в Reader.
- Обновления: SHA-256 и версии, установка DLL/UI, сохранение рабочих данных, откат файлов и восстановление прерванной операции.

## Windows

Готовые EXE и RepairClient.dll собираются LLVM-MinGW 20261104 (Clang 23.1.5) для Windows 10 x64. Таблицы импорта проверяются: дополнительных DLL компилятора нет. WebView2Loader.dll Microsoft импортирует только KERNEL32.dll; WebView2 Runtime устанавливается отдельно.

[Windows CI](https://github.com/ausziehen1/123asd/actions/workflows/repair-cards-windows.yml?query=branch%3Arepair-cards-stage1) собирает проект GCC/MinGW UCRT64 на Windows Server 2025 и выполняет все шесть групп тестов. В нативном запуске проверяются:

- окно Creator с нужным заголовком;
- подключение к настоящему C++ серверу;
- выбор десяти записей, добавление/удаление групп 1С, распределение 2/7/1, пустой код и блокировка при неверной сумме;
- размещение третьей строки в панели без обрезания;
- загрузка реального бланка WebView2 в Reader и Repair с правильным режимом документа.

Тот же сценарий запускается с готовыми EXE/DLL из полного ZIP. Журнал CI и отчет показывают фактический результат каждого этапа; полный успешный прогон нужен перед публикацией итоговой сборки.

Первый нативный прогон подтвердил сборку, шесть тестов и открытие Creator/Reader/Repair; ошибка выгрузки отчета из разных дисков устранена путем копирования отчета в каталог сборки.

## Проверки на пользовательском ПК

Версии 0.3–0.4.1 пользователь уже проверил на своем Windows 10: сервер, регистрация, редактирование/сохранение, запуск BarTender, QR и предпросмотр этикетки работают.

Для 0.5 остаются практические проверки на его Windows 10: масштаб интерфейса, USB-сканер, корпоративная сеть, установка Runtime при необходимости и физическая Zebra S4M с его носителем. Новый текстовый объект OneCCode нужно один раз добавить в рабочий BarTender-макет. Его печать не заявляется проверенной на физическом принтере в CI.
