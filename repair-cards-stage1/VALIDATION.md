# Проверка этапов 1 и 2.1

Проверено в рабочей среде Linux: GCC 14.2, CMake 3.31.6, SQLite 3.50.4.
Первый этап пользователь проверил на Windows 10 / CLion / MinGW64: тесты ядра, запуск сервера, создание пяти карточек и сохранение после перезапуска.
Оконный Креатор успешно собран для Windows x64 кросс-компилятором LLVM-MinGW 20261104 (Clang 23.1.5).
Запуск самого окна Креатора в Windows здесь не выполнялся. Архив содержит исходники и зависимости для сборки в CLion, без готовых EXE.

## Сборка и ядро — успешно

- Сборка C/C++ из включенных исходников библиотек, без загрузок зависимостей в CMake.
- Сохранение префикса, регистра и ведущих нулей ID, перенос разряда, длинные числовые суффиксы.
- Проверка количества, формата ID и несуществующего типа.
- Повторяющиеся внешние ID внутри одного типа и между типами.
- Уникальные внутренние номера, фильтрация и постраничная выдача.
- Бинарное сохранение шаблона и независимость копий у разных карточек.
- Откат всей партии при намеренно вызванной ошибке SQLite во второй записи.
- При откате подсказка следующего номера тоже остается прежней.
- Чтение записей после закрытия и повторного открытия базы.

## HTTP API — успешно

- Предпросмотр не создает записей.
- Создание типа и партии, чтение данных, фильтр и ссылки карточек.
- Скачанный бинарный XLSX полностью совпадает с исходным шаблоном.
- Неверные JSON-поля, числовое переполнение, отрицательные параметры и отсутствующие записи возвращают ошибки.
- Параллельно отправлены 12 запросов по 3 карточки: все 36 внутренних ID различны.
- После остановки и перезапуска сервера карточки и шаблоны сохранились.
- HTML экранирует введенные данные, включая строку с тегом script.

## Браузер — успешно

Playwright с установленным Chromium:

- Список тестовой партии V00001–V00005.
- Открытие карточки по внутреннему ID.
- В предварительном просмотре нет редактируемых полей.
- Открытие списка и карточки при ширине экрана 390 пикселей.

## HTTP-клиент Креатора — успешно

`client_tests` проверяет запросы здоровья сервера, типов, фильтрации и постраничной выдачи, предпросмотра и регистрации, обработку ошибок API и поврежденного ответа на регистрацию.
Адреса с неподдерживаемой схемой, путем, учетными данными или неверным портом отклоняются.
При потере ответа на регистрацию возвращается отдельная ошибка с требованием проверить список перед повтором; автоматического повторного POST нет.
Две группы тестов (`core_tests`, `client_tests`) успешно пройдены в Linux.
