# Проверка версии 0.4.0

Linux: GCC 14.2, CMake 3.31.6, SQLite 3.50.4. Windows x64: кросс-сборка LLVM-MinGW 20261104, Clang 23.1.5. Полный ZIP включает исходники и готовые EXE сервера, Креатора и Ридера.

Пользователь ранее проверил на Windows 10 / CLion / MinGW64 сервер, регистрацию, Креатор и редактор версии 0.3: создание, правки и сохранение работают. Новые окна 0.4, BarTender и физическая Zebra здесь не запускались.

## QR и задания BarTender — успешно

- Четыре группы C++ тестов, HTTP API и редактор в настоящем Chromium пройдены после изменений 0.4.
- Независимый zxing-cpp 2.3.0 читает сформированные QR; проверены полная ссылка, внутренний ID и белая зона QR.
- При одинаковом ProductID создаются разные ссылки по внутренним номерам.
- CSV сохраняет UTF-8, имена полей, кавычки, порядок и полную ссылку QRUrl.
- Проверены парсинг QR/номера, AIM-префикс сканера, отклонение произвольных ссылок и маршрута редактирования.
- Проверены выбор набора карточек, отсутствие регистрации при подготовке, сохранение server_id и public_url после перезапуска.
- Проверены запрет loopback в этикетках и отказ сетевой настройки при сервере, слушающем только localhost.
- Проверены формирование CLI BarTender, ручной диалог /FPD, отсутствие автоматической печати /P и экранирование аргументов Windows.
- Windows EXE успешно скомпонованы статически; таблицы импорта содержат только системные DLL Windows, без DLL компилятора.
- TEST-original.btw побайтно совпадает с загруженным TEST.btw. Файл не редактировался программно.
- Проверены запуск без аргументов с конфигом рядом с EXE из другой рабочей папки и отказ второй копии сервера на занятом порту. Сервер отключает совместное использование порта, чтобы запросы не попадали в разные процессы.

## Проверки на пользовательском ПК

- Запуск новых Креатора и Ридера на Windows 10 и при необходимости сборка в его MinGW64.
- Доступ телефона к серверу в корпоративной сети.
- Однократная привязка QRUrl, повторное открытие макета, реальные диалоги и предпросмотр в установленном BarTender 10.1.
- Выбор Zebra S4M, размер носителя, драйверные параметры, печать одной пробной этикетки и проверка сканирования; затем партия.

Они не заменяются кросс-компиляцией или независимым декодированием QR. Отчет не утверждает, что физическая печать уже проверена.

## Сборка и ядро — успешно

- Сборка C/C++ из включенных исходников библиотек, без загрузок зависимостей в CMake.
- Сохранение префикса, регистра и ведущих нулей ID, перенос разряда, длинные числовые суффиксы.
- Проверка количества, формата ID и несуществующего типа.
- Повторяющиеся внешние ID внутри одного типа и между типами.
- Уникальные внутренние номера, фильтрация и постраничная выдача.
- Бинарное сохранение шаблона и независимость копий у разных карточек.
- Откат всей партии при намеренно вызванной ошибке SQLite во второй записи.
- При откате подсказка следующего номера тоже остается прежней.
- Чтение записей после закрытия и повторного открытия базы.

## HTTP API — успешно

- Предпросмотр не создает записей.
- Создание типа и партии, чтение данных, фильтр и ссылки карточек.
- Скачанный бинарный XLSX полностью совпадает с исходным шаблоном.
- Неверные JSON-поля, числовое переполнение, отрицательные параметры и отсутствующие записи возвращают ошибки.
- Параллельно отправлены 12 запросов по 3 карточки: все 36 внутренних ID различны.
- После остановки и перезапуска сервера карточки и шаблоны сохранились.
- HTML экранирует введенные данные, включая строку с тегом script.

## Браузер — успешно

Playwright с установленным Chromium:

- Список тестовой партии V00001–V00005.
- Открытие карточки по внутреннему ID.
- В предварительном просмотре нет редактируемых полей.
- Открытие списка и карточки при ширине экрана 390 пикселей.

При компиляции стороннего SQLite GCC выдал одно предупреждение `-Wstringop-overread` в коде amalgamation; сборка завершилась, проверки прошли. Исходник SQLite не менялся.


## HTTP-клиент Креатора — успешно

`client_tests` проверяет запросы здоровья сервера, типов, фильтрации и постраничной выдачи, предпросмотра и регистрации, обработку ошибок API и поврежденного ответа на регистрацию.
Адреса с неподдерживаемой схемой, путем, учетными данными или неверным портом отклоняются.
При потере ответа на регистрацию возвращается отдельная ошибка с требованием проверить список перед повтором; автоматического повторного POST нет.
Четыре группы тестов (`core_tests`, `client_tests`, `document_tests`, `labels_tests`) успешно пройдены в Linux.


## Документы и обновление базы — успешно

`document_tests` создает реальную схему предыдущего этапа (версия 1), регистрирует карточку и открывает ее новым Store.
Проверено сохранение учетных ID, последовательности и XLSX при переходе на схему 2.
JSON и XLSX сохраняются атомарно; при ошибке SQL оба остаются прежними.
Проверены отказ устаревшему редактору, конкурирующее сохранение двух редакторов и чтение после перезапуска.
Некорректные размеры документа, опасные имена свойств и неверный base64 отклоняются.

## Редактор в браузере — успешно

`editor_test.py` запускает настоящий C++ сервер с базой предыдущей версии, Chromium через Playwright и проверяет:

- загрузку оригинального XLSX и учетного ID существующей карточки;
- реальный двойной щелчок и ввод в ячейку;
- Ctrl+S непосредственно во время ввода, без предварительного Enter;
- восстановление текста после обновления страницы;
- вставку строки и столбца с перемещением текста;
- полужирное оформление через панель инструментов;
- чтение полученного XLSX через openpyxl: значения, ID и полужирное начертание;
- конфликт двух открытых редакторов без потери сохраненной версии;
- просмотр без панели редактирования и без доступного ввода;
- открытие просмотра при размере окна 390×844;
- сохранение документа, XLSX и числа карточек после перезапуска сервера;
- отсутствие ошибок JavaScript и запросов к внешним ресурсам.

Обычные проверки API также повторно пройдены после обновления сервера.
