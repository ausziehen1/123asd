# API карточек

Все JSON-тела и строки — UTF-8. В примерах сервер доступен по `http://127.0.0.1:8080`.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/health` | Статус сервера и версии |
| GET | `/api/server-info` | Версия, постоянный server_id базы, public_url, local_only, сетевые адреса |
| PUT | `/api/settings/public-url` | Сохранить адрес сервера для QR |
| POST | `/api/labels/cards` | Получить выбранные карточки в порядке переданных внутренних ID |
| GET | `/api/platforms` | Типы, следующий ID и количество карточек |
| POST | `/api/platforms` | Добавить тип; существующее точное имя возвращает тот же тип |
| POST | `/api/batches/preview` | Диапазон без регистрации |
| POST | `/api/batches` | Зарегистрировать всю партию |
| GET | `/api/cards` | Список без бинарного содержимого XLSX |
| GET | `/api/cards/{id}` | Учетные данные одной карточки |
| GET | `/api/cards/{id}/workbook` | Текущий сохраненный XLSX; до первого редактирования — копия шаблона |
| GET | `/api/cards/{id}/qr.svg` | QR ссылки просмотра с сохраненным public_url |
| GET | `/api/cards/{id}/document` | Состояние редактора, revision и время сохранения |
| PUT | `/api/cards/{id}/document` | Атомарно сохранить документ и текущий XLSX с проверкой версии |
| GET | `/` | Временный список с фильтром |
| GET | `/cards/{id}` | Сохраненный бланк только для просмотра |
| GET | `/edit/{id}` | Свободное редактирование бланка в браузере |

Добавление типа:

```json
{"name":"Ноутбук 16.5"}
```

Предпросмотр партии:

```json
{"first_product_id":"V00001","count":5}
```

Создание партии:

```json
{"platform_type_id":1,"first_product_id":"V00001","count":5}
```

В ответе — `count`, `first_product_id`, `last_product_id`, `next_product_id`, `cards`.
Для каждой карточки возвращается `id`, `product_id`, `view_path`.
В `view_path` используется исключительно внутренний номер базы.

Фильтрация и постраничная загрузка:

```text
/api/cards?platform_type_id=1&limit=100&after=0
```

`platform_type_id=0` или отсутствие параметра означает все типы.
`after` — внутренний ID, после которого вернуть записи.
`limit` — от 1 до 1000, по умолчанию 100.
Следующая страница: передать в `after` последний `id` предыдущей.

Ошибки возвращают JSON `{"error":"описание"}`:

- 400 — неверное тело запроса, тип поля, число или формат ID;
- 404 — нет типа, карточки или маршрута;
- 500 — внутренняя ошибка, подробность записывается в консоль сервера.

ID продукции длиной не более 128 байт должен заканчиваться цифрами.
Числовая часть увеличивается как строка: большие номера не переполняют машинное целое.
Введенный регистр сохраняется: `V00001` и `v00001` не переписываются автоматически.

При несуществующем типе и при любой ошибке в середине вставки партия откатывается целиком, включая подсказку следующего ID.
На этом этапе нет API удаления карточки.

Сохранение документа:

```json
{
  "revision": 0,
  "document": {"format":"x-data-spreadsheet","version":1,"sheets":[]},
  "workbook_base64": "BASE64_XLSX"
}
```

Это описание полей, не готовый запрос: `sheets` должен содержать хотя бы один корректный лист, `workbook_base64` — текущий XLSX.
Ответ содержит новую `revision` и `updated_at`. HTTP 409 означает, что другой редактор уже изменил эту версию.
JSON и XLSX сохраняются в одной транзакции. GET `/workbook` возвращает текущий сохраненный XLSX; до первого редактирования — индивидуальную копию шаблона.

## QR и настройки

PUT `/api/settings/public-url`: `{"public_url":"http://192.168.1.50:8080"}`. Возвращает актуальный `/api/server-info`. Loopback, wildcard, URL с путем/учетными данными и сервер с конфигурацией только localhost отклоняются. Адрес сохраняется в SQLite; необязательный `public_url` в конфиге задает только начальное значение, если сохраненного еще нет.

POST `/api/labels/cards`: `{"ids":[2,1]}`. Возвращает массив карточек в заданном порядке; разрешены 1–1000 положительных внутренних ID. Отсутствующая карточка — 404. Создания/редактирования записей нет. Генератор задания клиента исключает повтор одного внутреннего ID в задании.

GET `/api/cards/{id}/qr.svg` требует существующую карточку и настроенный public_url. Кодируется обычная ссылка `/cards/{id}`, не маршрут редактирования. Настройки QR не ограничивают права API: авторизации в согласованном объеме нет.

## Коды 1С — версия 0.5.0

Схема SQLite 4: `cards.one_c_code TEXT NOT NULL DEFAULT ''`. В JSON карточки добавлены `one_c_code` и `document_revision`. Ответ `/document` также содержит one_c_code из того же снимка, что revision/document; это важно при одновременном назначении кода и загрузке бланка.

POST `/api/labels/assign`:

```json
{
  "cards": [{"id":1,"revision":0},{"id":2,"revision":0}],
  "groups": [{"count":1,"code":"00123"},{"count":1,"code":""}]
}
```

Назначение идет в порядке массива cards. Уникальные положительные ID, 1–1000 карточек, положительное количество в каждой группе, сумма строго равна числу карточек. code — строка до 128 байт без управляющих символов, пустая допустима. Один внутренний ID нельзя повторять.

Ответ — актуальные карточки в том же порядке. Измененные коды записываются в колонку, JSON и XLSX в одной транзакции, увеличивая ревизии. Неизмененный код не увеличивает ревизию. При конфликте версии — 409 и откат всей операции; при отсутствии карточки — 404 и откат. Потерянный ответ может означать уже выполненное назначение: сначала повторно загрузите данные.

Ячейка JSON помечается `repairField: "one_c_code"`; ее положение переносится при структурных операциях редактора. XLSX использует именованную область RepairCards_OneCCode. Сохранение документа извлекает значение этой ячейки и обновляет колонку вместе с документом; все действует в рамках прежней проверки revision.

`/api/server-info` добавляет capabilities `one_c_v1`, `embedded_view_v1`. Встроенные клиенты используют прежние `/cards/{id}` и `/edit/{id}` с `?embedded=1`. Режим Reader остается read; отдельной авторизации по ролям нет.
