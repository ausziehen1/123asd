# Версия 0.5.0: Creator, Reader, Repair и обновления

## 1. Обновление работающего проекта

1. Сохраните открытые бланки. Закройте клиенты и остановите сервер.
2. Скопируйте папку `data` и свои конфиги в резервное место. Дополнительно сохраните `%LOCALAPPDATA%\RepairCards`: там настройки и ваш рабочий макет BarTender.
3. Распакуйте полный архив. Содержимое `RepairCards-stage1` скопируйте в существующий проект с заменой исходников. Рабочей базы в архиве нет.
4. В `ready-windows/config.example.json` проверьте путь базы. По умолчанию `../data/repair.sqlite3` указывает на прежнюю папку `data` проекта. Для нестандартного пути перенесите свое значение. Порт также должен совпадать с прежним.
5. Запустите **`ready-windows/repair_server.exe`**. Консоль должна показать `Repair Cards 0.5.0` и правильный путь базы. Оставьте ее открытой.
6. Запустите **`Creator.exe`** из той же папки. Теперь EXE называется Creator, а логика находится рядом в `RepairClient.dll`.

При запуске сервер автоматически обновит схему до **4**. Он добавит `one_c_code`, сохранив учетные номера, последовательности и бланки. Если код 1С уже заполнен в старом бланке, сервер извлечет его при миграции. Для возврата к серверу 0.4 нужна резервная копия базы до миграции.

Для запуска из CLion выполните Reload CMake Project и соберите `repair_server`, `repair_creator`, `repair_reader`, `repair_repair`, `repair_updater`. Target `repair_creator` создает Creator.exe и собирает общую DLL. Аргументы сервера прежние: `--config config.example.json`, рабочая папка — корень проекта. Готовые EXE и сервер из CLion одновременно запускать не следует.

## 2. Распределение кодов 1С

1. Подключитесь в Creator и выберите существующие карточки (Ctrl/Shift для нескольких) либо используйте «QR последней партии».
2. Откройте «QR / BarTender». Отображается **«Количество номеров»**.
3. В строках слева задайте **количество** и **код 1С**. Справа у последней строки «+» добавляет новую группу; у предыдущих строк «−» удаляет группу. Если групп много, используйте прокрутку.
4. Например для десяти номеров: `2 / 123`, `7 / 1234`, `1 / 12345`. Если код общий, достаточно одной строки `10 / код`.
5. Для номеров без кода задайте количество и оставьте код пустым. Количество в каждой строке — положительное целое.
6. Справа показано точное назначение по **Unique ID / Table ID / 1C Code** в порядке списка. Сумма количеств должна совпасть с числом выбранных карточек. Пока она не совпала, «Сформировать QR» недоступна.
7. Выберите доступный из вашей сети адрес сервера и нажмите **«Сформировать QR»**.

Программа одновременно назначит коды выбранным карточкам, обновит поле бланка и XLSX и подготовит CSV для BarTender. Повторные Table ID не смешиваются: привязка идет по Unique ID. Если другой редактор уже изменил один из бланков, вся операция назначения откатывается. Закройте окно подготовки, обновите карточки и повторите распределение по актуальным данным.

Если ответ сервера потерян, назначение могло сохраниться. Откройте окно подготовки заново: оно получит актуальные коды и версии. Автоматического повторного сохранения нет.

Для обычной повторной печати уже сохраненные коды подставляются в группы автоматически. Формирование QR при неизменных кодах не меняет версии документов.

## 3. Один раз добавить код 1С в рабочий макет BarTender

Ваш сохраненный `%LOCALAPPDATA%\RepairCards\labels\RepairCards.btw` остается прежним. Исходный TEST-original.btw не заменяет рабочий макет. Новое поле данных называется **`OneCCode`**.

1. Сформируйте QR для пробной карточки, затем откройте **«Макет(BarTender)»**.
2. Добавьте текстовый объект в нужном месте этикетки.
3. В его свойствах выберите источник **«Поле базы данных» → `OneCCode`**. QR-объект по-прежнему связан с `QRUrl`.
4. Сохраните рабочий макет Ctrl+S.
5. Откройте «Предпросмотр / печать» и проверьте «Образец» для нескольких записей.

Поле OneCCode содержит только код: пустое значение дает пустой текстовый объект. При необходимости подпись «Код 1С» добавляется и оформляется в BarTender. В источнике QR и кода отключите приращение/сериализацию: значения уже подготовлены программой.

CSV теперь содержит `InternalID,ProductID,Platform,QRUrl,OneCCode`. Если новое поле не появилось в списке, через параметры соединения с базой данных выберите `labels.csv` текущего задания, укажите заголовки первой строки, разделитель-запятую, двойную кавычку и UTF-8.

Выбор Zebra S4M ZPL, размер носителя, качество/насыщенность и точный предпросмотр выполняются в штатном диалоге BarTender. Для первого прогона напечатайте одну запись, отсканируйте ее и сверьте код 1С и карточку.

Двоичный BTW в Linux программно не редактировался. Привязка нового текстового объекта выполняется штатно в вашем BarTender один раз. Прошедшая у пользователя проверка QRUrl и запуска BarTender сохранена.

## 4. Reader и Repair

Для коллег есть отдельные комплекты Reader и Repair. Это портативные комплекты: распакуйте их в папку с правом записи, например на рабочий стол. Распаковывать нужно **всю папку**, сохраняя DLL и файлы рядом с EXE.

- **Reader.exe:** ввод/сканирование QR или внутреннего числового ID, затем отдельное встроенное окно просмотра.
- **Repair.exe:** такой же ввод, затем встроенное окно того же бланка с редактированием и сохранением. Ctrl+S работает внутри бланка.
- Enter в поле QR равнозначен кнопке **«Открыть»**.
- Полная QR-ссылка задает адрес сервера. Для внутреннего числового ID сначала задайте адрес вручную.
- После успешной проверки адрес сохраняется, поле скрывается и становится неактивным. Нажатие на надпись **«Сервер»** снова показывает его. Enter в поле сервера подтверждает адрес.
- Окно бланка подстраивается под содержимое и доступный экран. Длинный бланк прокручивается. При следующем открытии используется то же окно.
- Для следующего сканирования вернитесь в поле QR основного окна.
- Repair спрашивает о сохранении правок при смене карточки и закрытии. Отказ от перехода оставляет текущий бланк открытым. Конфликт редакторов не перезаписывает чужую сохраненную версию.

Встроенное отображение требует **Microsoft Edge WebView2 Runtime, Evergreen x64**, установленный один раз на клиентском ПК. Маленький WebView2Loader.dll включен в комплект; сам Runtime — отдельный системный компонент Microsoft. Если он отсутствует, окно покажет понятное сообщение.

[Официальная загрузка WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/#download-section). В корпоративной сети можно получить Evergreen Standalone Installer x64 на ПК с Интернетом и передать установщик через ваш ИТ-отдел. После установки перезапустите клиент. В обычной работе клиенту нужен только доступ к вашему серверу.

На телефонах QR по-прежнему открывает бланк обычным браузером. Windows-клиенты используют встроенное окно.

## 5. Где находится код 1С

В SQLite это текстовая колонка `cards.one_c_code`, в списке — **1C Code**. Ведущие нули сохраняются.

Редактор помечает ячейку поля служебной привязкой. При вставке строк и столбцов она перемещается вместе с ячейкой. В XLSX дополнительно записывается именованная область `RepairCards_OneCCode`. На сохранении бланка код в таблице, SQLite и текущем XLSX обновляется вместе.

Для очистки оставьте пустое значение после «Код 1С:» или очистите текст привязанной ячейки. Если удалить само поле при непустом сохраненном коде, сервер попросит восстановить его: код не должен теряться из-за случайного удаления строки.

## 6. Локальные обновления

В комплекте:

- **Creator.exe / Reader.exe / Repair.exe** — небольшие запускающие приложения с QR-иконкой.
- **RepairClient.dll** — общая логика и интерфейс клиентов, ABI 1.
- **WebView2Loader.dll** — загрузчик Microsoft для встроенного бланка.
- **Updater.exe** — отдельный обновляющий модуль, который работает и при поврежденной клиентской DLL.
- **installation.json** — версия установленного комплекта.
- **theme.json** — спокойная цветовая схема и шрифт интерфейса.

Для последующих версий вы получите локальный ZIP-патч. В меню окна (нажмите на QR-иконку слева в заголовке) есть **«Локальное обновление…»**; также можно напрямую запустить Updater.exe.

1. Сохраните бланки и закройте Creator, Reader и Repair из обновляемой папки.
2. Запустите Updater.exe из этой папки.
3. Выберите ZIP-патч. Модуль проверит исходную версию, ABI, архитектуру и SHA-256 файлов.
4. Нажмите «Установить». Старые файлы сохраняются в `.updates/backup-…`.
5. Запустите нужный клиент. «О программе…» показывает установленную версию.

Кнопка **«Откатить обновление»** восстанавливает файлы предыдущего клиентского обновления. При прерывании установки запускающие EXE обнаружат журнал и предложат Updater.exe для восстановления. Обновление не подменяет рабочую SQLite, конфиги сервера, бланки и рабочий макет BarTender. Локальные клиентские патчи не мигрируют схему сервера.

Часть функций находится в нативном C++: изменение этой логики требует сборки новой **DLL**. Стабильные EXE при обычном обновлении DLL пересобирать и заменять не требуется. Цвета и шрифт меняются в theme.json; рабочий Excel-бланк и макет BarTender редактируются своими штатными средствами. При изменении ABI или обновляющего механизма понадобится новый полный комплект.

## Для разработчика патчей

Обновите версию проекта CMake, соберите Release-цель `repair_client`. Рядом с DLL появится installation.json новой версии. Затем стандартным Python:

```text
python scripts/make_patch.py --client-dir ПАПКА_СБОРКИ --from-version 0.5.0 --version 0.5.1 --output RepairCards-0.5.0-to-0.5.1.zip
```

По умолчанию патч содержит RepairClient.dll. Для дополнительных файлов укажите `--file RepairClient.dll --file theme.json` и т. п. В патчах разрешены клиентские EXE, две указанные DLL, theme.json и ограниченный набор ui-файлов. Рабочая база, шаблоны пользователя и Updater.exe в такой патч не включаются. Версия клиента и совместимость серверного API должны быть проверены до распространения.

## Проверки

Шесть групп C++ тестов проверяют базу, API-клиент, документы, QR, коды 1С и обновления. Браузерные тесты проверяют реальный ввод, перемещение поля 1С при вставке строки/столбца, именованную область XLSX, синхронизацию SQLite и сообщения встроенного окна.

Windows CI собирает исходники GCC/MinGW и проверяет открытие Creator и загрузку реального бланка WebView2 в Reader/Repair с нужным режимом. Отдельно проверяются готовые EXE полного архива. Результаты и границы проверки: [VALIDATION.md](../VALIDATION.md). Физическая Zebra и пользовательский макет проверяются отдельно на вашем ПК.
