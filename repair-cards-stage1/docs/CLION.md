# Первый запуск в CLion с MinGW64

Обновление существующего проекта, QR и печать: **[QR_PRINT_READER.md](QR_PRINT_READER.md)**. Регистрация партий: **[CREATOR.md](CREATOR.md)**.

Visual Studio и MSVC для этого проекта не нужны. Используем установленный MinGW64.

## 1. Открыть проект

Распакуйте проект, например, в `C:\RepairCards\stage1`.
В CLion выберите **File → Open** и укажите папку с `CMakeLists.txt`.
Если IDE спрашивает, открыть ли как CMake-проект, выберите этот вариант.

## 2. Проверить компилятор

Откройте **Settings → Build, Execution, Deployment → Toolchains**.

- Toolchain: **MinGW**.
- Toolset: ваш установленный MinGW64 либо Bundled MinGW.
- C Compiler: `gcc.exe`.
- C++ Compiler: `g++.exe`.
- CMake: можно **Bundled**.
- Build Tool и Debugger: выбранные CLion для этого toolchain.

Все инструменты должны определиться без ошибок.
Компилятор должен поддерживать C++17. Если сборка сообщит об отсутствии `std::filesystem`, сначала проверим версию GCC.

## 3. Проверить CMake-профиль

Откройте **Settings → Build, Execution, Deployment → CMake**.
В профиле установите:

| Параметр | Значение |
|---|---|
| Toolchain | Ваш MinGW |
| Build type | Debug |
| Build directory | `build/mingw-debug` |
| CMake options | Пусто |
| Generator | По умолчанию; встроенный Ninja подходит |

Нажмите **Apply**, затем дождитесь окончания загрузки CMake.
Генератор Visual Studio выбирать не нужно.
Профилю можно оставить его текущее имя.

## 4. Настроить запуск

В списке целей рядом с кнопкой запуска выберите **repair_server**.
Откройте **Run → Edit Configurations** для этой цели:

- **Program arguments:** `--config config.example.json`
- **Working directory:** корневая папка проекта, где лежат `CMakeLists.txt` и `config.example.json`.
- **CMake profile:** настроенный профиль MinGW / Debug.

Рабочая папка важна: хотим сохранять базу в одной папке `data` проекта, независимо от конфигурации сборки.

## 5. Собрать и запустить

Нажмите **Build**, затем **Run** для `repair_server`.

Ожидаемые строки в консоли:

```text
Repair Cards 0.4.1
Database: .../data/repair.sqlite3
Listen: http://0.0.0.0:8080
Stop: Ctrl+C
```

Откройте http://127.0.0.1:8080 в браузере на этом ПК. Пока список пуст.
Сервер оставьте работающим в CLion.

## 6. Зарегистрировать тестовую партию

Оставьте сервер работающим и запустите цель **repair_creator**. Нажмите «Подключить», добавьте тип через «+», задайте начальный ID и количество. Кнопка «Проверить диапазон» не создает записей; «Создать партию» сначала показывает подтверждение. Подробности: [CREATOR.md](CREATOR.md).

В браузере появятся зарегистрированные карточки.
Остановите сервер кнопкой Stop в CLion, запустите снова и обновите страницу — карточки должны сохраниться.

## Проверки ядра

Для запуска проверок выберите цель **core_tests** в CLion и нажмите Run.
Ожидается `Core tests passed`.

## Необязательная сборка без IDE

Если `cmake`, `gcc`, `g++` и `mingw32-make` доступны в PATH, можно использовать `01_build.cmd`.
Он создает отдельную папку `build/mingw64` с генератором **MinGW Makefiles**.
Затем `02_start_server.cmd` запускает этот сервер с рабочей папкой в корне проекта.
Для работы через CLion настраивать PATH ради этих скриптов не требуется.

Если меняете генератор или компилятор, используйте новую папку сборки либо **Reset Cache and Reload Project**.

## Если возникла ошибка

Нужны первая ошибка из окна Build и вывод `g++ --version` для выбранного компилятора.
Дополнительные SQLite, Python, Node.js или Qt на этом этапе не требуются.
