# Согласованные требования

## Назначение

Локальный учет некондиционного оборудования и заполнение карточек ремонта.
Сервер и SQLite находятся на постоянно включенном ПК с Windows 10.
Карточки должны открываться в локальной сети с компьютеров и телефонов.

## Идентификаторы и партии

- Внутренний ID назначает SQLite, независимо от введенного номера продукции.
- ID продукции задает администратор или помощник. Например `V00001`.
- ID продукции может совпадать у разных записей; он не является уникальным ключом.
- Тип платформы задается отдельным полем: существующий из списка или новый через «+».
- Партия задается типом платформы, начальным ID и количеством.
- Увеличивается завершающая числовая часть ID с сохранением префикса, регистра и ведущих нулей.
- Следующий предлагаемый ID хранится для каждого типа платформы отдельно.
- Предложение следует за последней успешно созданной партией данного типа, включая ручную смену начального ID. Это не поиск максимального номера во внешнем учете.
- Вся партия создается одной транзакцией.
- Список карточек фильтруется по типу платформы.
- Источником номера служит ручной ввод: интеграция с чужими учетными таблицами не требуется.

## Документ

- Общий исходный Excel-шаблон предоставлен пользователем: `templates/blank.xlsx`.
- Заголовок: «Карточка некондиционного товара».
- Шапка: ID, заказ, наименование товара / модель / Part.No, код 1С.
- Таблица: №, дата, № акта, наименование узла, описание неисправности/дефекта, ответственный / ФИО.
- В образце восемь позиций; это не ограничение количества записей в будущем редакторе.
- Каждая регистрация получает отдельную копию шаблона.
- Существующий бланк продолжают редактировать и дополнять. Новые отдельные акты при каждом изменении автоматически не создаются.
- Должно быть свободное редактирование таблицы: значения, строки, столбцы, объединения, размеры и оформление.
- Внешний вид соответствует образцу. Полная совместимость со всеми функциями Excel не требуется.
- Бланки можно оставить незаполненными. Печать бланков не нужна.
- Совпадающие ID продукции не объединяют документы.

## Приложения

- Два отдельных приложения: «Креатор» и «Ридер».
- Креатор: создание типов, регистрация партий, редактирование и печать QR.
- Ридер: сканирование / ввод QR и просмотр, без редактирования.
- Без входа, учетных записей и паролей. При необходимости их добавят позже.

## Печать

- Печатаются только QR-этикетки.
- У пользователя Zebra S4M ZPL и BarTender 10.1 SR3 build 2950. Размер и расположение задаются в макете BarTender и проверяются по установленному носителю.
- Выбор принтера и доступных драйверу настроек обязателен.
- Предоставлен макет TEST.btw с QR. Редактирование макета, расположение, точный предпросмотр и свойства принтера — через BarTender. ID продукции и тип можно добавить текстовыми полями в макет.
- QR однозначно указывает на внутренний ID записи; учетный номер сам по себе для ссылки недостаточен.

## Текущее состояние: 0.4.1

Сделаны ядро SQLite, сервер, API регистрации и фильтрации, просмотр сохраненного документа и отдельное Windows-приложение Креатор для регистрации партий и списка карточек.
Креатор показывает выпадающий список типов, кнопку «+», следующий предложенный ID, предпросмотр диапазона, подтверждение регистрации и постраничный список с фильтром.
Сетевые запросы выполняются в фоне. При потере ответа на регистрацию автоматического повтора нет.
Реализован редактор в браузере: импорт собственного XLSX карточки, изменение ячеек и оформления, вставка/удаление строк и столбцов, объединения, сохранение JSON и текущего XLSX.
Сохранение проверяет ревизию документа и выполняется атомарно. Старый редактор не может затереть новую сохраненную версию.
Обычная ссылка карточки открывает сохраненный документ только для просмотра. Добавлены отдельный Windows-Ридер, сканирование QR в Креаторе, QR выбранных записей/последней партии, сохраняемый сетевой адрес и задания CSV для BarTender.
Креатор открывает рабочий .btw для редактирования либо стандартный диалог печати BarTender. При первом подключении исходного шаблона QR-объект нужно связать с полем QRUrl. Саму печать пользователь запускает из BarTender.
Сборка Windows EXE проверена через LLVM-MinGW; фактический запуск новых окон и BarTender, телефон в корпоративной сети и физическая Zebra проверяются на пользовательском ПК.

## Структура SQLite

`cards` — общая таблица оборудования и документов. Не создаем новую таблицу на каждый тип.

| Поле | Назначение |
|---|---|
| id | Внутренний уникальный номер AUTOINCREMENT |
| product_id | Введенный номер продукции, повторы разрешены |
| platform_type_id | Ссылка на справочник типов |
| workbook | Текущий XLSX в формате BLOB; до первого сохранения — копия шаблона |
| document_json | Сохраненное состояние таблицы или NULL до первого редактирования |
| document_revision | Версия документа для защиты от перезаписи |
| document_updated_at | Момент последнего сохранения в UTC |
| created_at | Момент регистрации в UTC |

`platform_types` — небольшой справочник для выбора типа и подсказки следующего номера.
`app_settings` — постоянный идентификатор базы и сетевой адрес QR; добавлена в схеме 3.
Техническую версию схемы хранит `PRAGMA user_version`.

Имена типов уникальны при точном совпадении строки; выбор доступен в Креаторе.
Лимит одной партии — 1000 карточек.

## Дополнение 0.5.0

- Три приложения: Creator (полные возможности), Reader (встроенный просмотр), Repair (ввод QR и встроенный редактор с сохранением).
- Код 1С назначается выбранным номерам группами «кол-во / код 1С». «+» справа у последней строки добавляет следующую, «−» у остальных удаляет строку. Сумма количеств равна числу номеров. Код может быть пустым.
- Назначение видно в предварительной таблице. Значения сохраняются по Unique ID и синхронизируются с бланком и XLSX, в том числе после вставки строк/столбцов.
- Новый CSV-столбец OneCCode выводится отдельным текстовым объектом BarTender. QRUrl остается ссылкой просмотра.
- Согласованные новые названия кнопок и колонок применяются в Creator; главное окно называется Creator.
- QR-иконка присутствует в EXE, заголовках окон и ярлыках. Общая спокойная тема задается внешним theme.json.
- Reader/Repair скрывают подтвержденный сервер, показывают его по нажатию на «Сервер». Enter в поле QR равнозначен «Открыть».
- Окно бланка встроенное, подстраивается под бланк и экран. Повторное открытие использует это окно; Repair защищает несохраненные правки.
- Клиентская логика вынесена в RepairClient.dll, запускающие EXE используют стабильный ABI. Updater.exe устанавливает локальные ZIP-патчи с версиями, хешами, резервной копией и откатом.
- Схема 4 добавляет текстовый one_c_code; рабочие данные сохраняются при обновлении.
